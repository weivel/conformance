The vectors are weivel's behaviour written down as data rather than as a test suite inside one implementation. A vector is one JSON file under `vectors/` that names a given state, one operation and the outcome any engine must produce: its `id`, its `op`, what it `covers` (a section of weivel's design, `12.1` to `12.6`, one of its invariants, `invariant-1` to `invariant-14`, or `host`, the host contract of the standard's `weivel/host.h`), its `given` and its `then`. The vectors live outside every implementation on purpose: an engine whose own repository holds its conformance suite defines its own exam, and the first thing it does when the suite disagrees with it is change the suite. So the core, the standard and every language implementation are held to one corpus, whatever language each is written in.

- [layer/](layer/) - the vectors only a language layer can witness, op by op, and what each language's suite must do to witness them
- [then.md](then.md) - what a vector's `then` can assert, and how each assertion is compared with an answer
- [tiers.md](tiers.md) - the three tiers (`core`, `standard`, `layer`), which suite judges each, who runs them, and how a vector's id follows its path
