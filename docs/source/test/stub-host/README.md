`stub-host`, the kit's stub provider of `weivel.host` and `weivel.scope` (the standard's `weivel/host.h` and `weivel/scope.h`), which a language's host program is run against by the `host` layer vectors. Its run is read from the `stub-host.json` in the directory its `start` is handed, and everything it is told is appended to `record.txt` there; the shape of both, and the order the vectors judge the record in, are defined by [the `host` op](../../../vectors/layer/host.md). It is a test library only and names nothing of any application. How a suite builds it, why each description is reached through a forwarder, and why every call takes one lock are in that doc too. The modules share one `stub_run` through `run.h`, `lock.c` holds that one lock, and the library hides every symbol but those `stub_host.h` exports. A run's memory lives until the next `start` replaces it, so an answer handed to the program stays valid across its later calls, and an answer written for a consumer compiled against an older, smaller struct is filled only within the size that consumer gave. The three declarations beside the sources (`library.json`, `library-declares-log.json`, `library-declares-a-contract.json`) are the ones a vector's plan loads it under.
