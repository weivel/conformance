The benchmarks folder holds the core control call benchmark and every timing budget weivel holds, as data beside the one program that measures the core; what each budget means and how each number was measured is in [the benchmarks doc](../../benchmarks.md). `budget.txt` is the core's, `c.txt`, `java.txt` and `typescript.txt` the languages'. The program links the core alone and reads its clock monotonically (`QueryPerformanceCounter` on Windows, `CLOCK_MONOTONIC` elsewhere); its exit codes keep a broken budget apart from a slow core. Its tests run it against malformed and impossible budgets under `test/fixtures/benchmark/`. Every `<language>.txt` in this folder gets a `language_budget_of_<language>_is_well_formed` test without a line of CMake, so a new language's file is checked the moment it lands.
