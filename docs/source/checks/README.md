The checks folder builds the five drift check programs, `weivel-purity`, `weivel-names`, `weivel-parity`, `weivel-layers` and `weivel-core-gate`, and holds the three lists they read: `languages.txt` (what each language's files, roots and exemptions are), `names.txt` (the words no weivel file may carry) and `core_gate.txt` (what the built core may import and its sources may name). What each program allows, refuses and skips is in [the drift checks doc](../../checks.md). The folder's CMake also holds the kit to its own rules (`kit_is_pure`, `kit_names_no_foreign_word`), pins both lists (`names_list_holds_the_nine_words`, `languages_list_holds_the_pinned_lines`) so a list changes only together with its test, runs the core gate over the real pinned core (`core_reads_nothing_of_the_world`, `core_sources_read_nothing_of_the_world`), and registers every planted scenario of `test/checks_test.cmake` and `test/core_gate_test.cmake`, building the core gate's fixture libraries from `test/fixtures/core-gate/`. A core gate scenario written for another platform reports as skipped, never as passed.
