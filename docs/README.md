The conformance kit is weivel's exam: the one place that says what every weivel engine must do, and the checks that hold every weivel repository to its rules. It owns four things. The vectors are weivel's behaviour as data, each a given state, one operation and the outcome any engine must produce, in three tiers: the core's, the standard's, and the layer vectors only a language implementation can witness. The runner, `weivel-conformance`, is a C program that loads the vectors and judges the core and the standard against theirs in-process, through one adapter per op linked against both; it does not run the layer vectors, which each language's own suite witnesses by naming every one in its tests, so the C, Java and TypeScript implementations are held to the same corpus and behave the same where it reaches. The drift checks are five C programs that each weivel repository's drift job runs, those that apply to it, against the kit at a pinned commit: purity (a repository holds only its own language), names (no foreign word), parity (a language implements the core's modules), layers (a language's tests name every layer vector) and the core gate (the built core reads nothing of the world and its interface hands it nothing it could call). The benchmark budgets are every timing bound weivel holds, the core's control call and each language's ratios, so no implementation sets its own. The kit implements no part of weivel and holds no engine: it builds the core and the standard from checkouts at `siblings/core` and `siblings/standard`, pinned by commit in `repo.json`, and its own tests sit those pins against their tiers, run every check against planted trees, and build `stub-host`, the stub provider a language's host program is run against.
